# 분석 노트 — `GLMM_analysis.ipynb` 방법·근거

노트북은 모형 식(fixed/random)과 결과 표만 담는다. 그 배경 설명을 여기에 모은다.
방향 효과 탐색은 별도로 [`exploratory_direction.md`](exploratory_direction.md) 에 있다.

## 왜 lme4 인데 이항 GLMM 이 아닌가

`model_equations.md` 의 사양은 이항 `glmer(family=binomial, weights=n)` 이다. 그러나 CSV 에는
정답 비율만 있고 **분모 n 이 없다.** 이항 가능도를 쓸 수 없으므로 원척도 `lmer` 로 간다.
- 계수는 logit 이 아니라 **정확도 단위**로 읽는다 (예: `trained_yet` +0.34 = 정확도 34%p 상승).
- 정규 응답에서는 잔차분산이 자유모수라 사양의 OLRE `(1|obs)` 는 중복이므로 뺀다.

## 응답변수 — delta

$$\texttt{delta} = \texttt{acc} - \texttt{base}$$

`base` 는 학습 전(t0) 정확도. `metric` 이 `mae` 인 태스크(S1)는 `1 - MAE` 로 뒤집어
"높을수록 좋음"으로 통일한다.

**delta 냐 acc 냐는 계수를 바꾸지 않는다.** `base` 를 이미 공변량(`base_wi + base_bw`)으로
넣으므로 `delta ~ X` 와 `acc ~ X` 는 재매개화 관계다 — `trained_yet`·`direction` 등 계수와 p값이
소수점 4자리까지 같고, `base_wi`/`base_bw` 계수만 정확히 1씩 이동한다. 차이는 **R² 의 분모**에만
있다. `acc` 를 응답으로 두면 분모가 `base` 분산에 압도되어 probing 에서 R² 가 0.99 로 포화된다
(그저 acc≈base 라는 뜻). `delta` 로 두면 분모가 "학습이 바꾼 양"이 되어 네 분석의 R² 가 같은
기준에서 비교된다.

### 퍼센트 변화나 정규화이득은 왜 안 쓰나

- 퍼센트 변화 `(acc-base)/base`: `base` 가 0.015 인 셀이 있어 분모가 터진다(+5,562%). 못 쓴다.
- 정규화이득 `(acc-base)/(1-base)` (Hake): 천장을 보정하지만 결론을 안 바꾼다. probing 깊이별로
  보면 여유가 가장 큰 layer_0 이 가장 안 변하고 여유가 가장 작은 최심층이 가장 많이 변한다 —
  **천장효과의 반대 방향**이라, 정규화해도 층별 격차(350배)가 그대로 남는다. 절대 delta 를 쓰되
  천장이 원인이 아님만 확인해 두면 된다.

## 변수 정의

한 행 = 한 모델이, 한 방향으로 학습하다가, 어느 세션 종료 시점에, 한 태스크(probing 은 한 층)를
평가한 결과.

| 변수 | 정의 | 비고 |
|---|---|---|
| `acc` | 정확도 (mae 는 1-MAE) | 응답의 원재료 |
| `base` | 학습 전 정확도 | |
| `delta` | `acc - base` | **응답변수** |
| `base_bw` | 모델별 `base` 평균 | 그림 라벨 **model mean perf.** — 「전반적으로 좋은 모델인가」. 모델이 5개뿐이라 **모델 정체성과 거의 중복** |
| `base_wi` | `base - base_bw` | 그림 라벨 **task-specific perf.** — 「그 모델이 이 태스크를 유난히 잘하는가」. 모델 수준과 독립 |
| `time` | 1..5 | 누적 학습 세션 수 (mid 체크포인트는 버림, 아래 참조) |
| `time_c` | `time - 3` | 중심화 |
| `trained_yet` | 0/1 | 이 시점에 **자기 태스크 세션이 끝났는가**. 커리큘럼 전용 |
| `recency` | 0,1,2… | 자기 세션 종료 후 경과 세션 수 (미학습이면 0) |
| `direction` | forward/reverse | 커리큘럼 방향. **평균차만** (기준 = forward; 아래 「방향 기준」 참조) |
| `depth_num` | 0~1 연속 | 상대 표상 깊이 (probing). 그림 라벨 **depth (slope)**. 모델별 정규화 |
| `is_proj` | 0/1 | proj(비전→언어 프로젝터) 지시변수. 그림 라벨 **proj (vs layer_0)** |
| `model`, `task` | 5 / 5·10수준 | |

### mid 체크포인트 제거

각 세션은 `S*_mid`, `S*_end` 두 번 평가된다. 둘은 값이 거의 같아 사실상 중복 관측이라
`S*_end` 만 쓴다. 남기면 표본이 두 배로 부풀어 표준오차가 부당하게 작아진다.

### 초기 성능을 둘로 쪼개는 이유

`base` 를 통째로 넣으면 「모델이 원래 좋다」와 「이 태스크를 원래 잘한다」가 섞인다.
between(`base_bw`, 그림 라벨 *model mean perf.*)/within(`base_wi`, *task-specific perf.*)
분해로 분리한다. 응답이 `delta` 라 이 계수들은 "초기값이 높으면 덜 오르는가(천장·평균회귀)"로
읽는다 — 그래서 부호가 음수로 나오는 것이 정상이다.

### 「순서」의 두 정의 — 결론이 갈리는 지점

- `direction` = forward 집단 vs reverse 집단의 **평균** 차이 → 네 분석 모두 널.
- `trained_yet`/`recency` = 각 태스크를 **언제** 배웠나 → 압도적(ΔR²≈0.21).

두 방향은 결국 같은 5개 세션을 다 돌기 때문에 평균은 같다. 순서가 만드는 차이는 태스크 안에 있고
(S0 은 forward 에서 1번째·reverse 에서 5번째 세션에 학습), 태스크마다 정반대라 평균 내면 상쇄된다.
따라서 **"커리큘럼 순서는 효과가 없다"가 아니라 "방향의 주효과는 없고, 작용하는 것은 각 태스크의
학습 시점"** 이 정확한 서술이다.

## 랜덤효과

| 항 | 흡수하는 것 |
|---|---|
| `(1\|task)` | 태스크 고유 난이도 |
| `(1\|model:task)` | 모델×태스크 궁합 + 같은 셀 반복측정 의존성 |
| `(1\|model)` | 모델 고유 수준 (최종 모형에서만) |
| `(1\|cell)` | 같은 체크포인트의 6개 층이 공유하는 표상 수준 (probing 전용) |

## R² 귀인 방식

전체 모형을 고정하고 각 요인을 **하나씩 빼서** R²(Nakagawa 주변 R²)가 얼마나 떨어지는지 본다
(forward selection 이 아니라 정해진 모형 안의 분산 분해). 요인끼리 공유하는 몫이 있어
**고유 기여의 합은 전체 R² 와 일치하지 않는다.** 고정효과 비교를 위해 `REML=FALSE`.

## 네 분석의 모형 구성

공통 fixed: `base_wi + base_bw`. 공통 random: `(1|model)+(1|task)+(1|model:task)`.

| 항 | inf 커리 | prob 커리 | inf bench | prob bench | 이유 |
|---|:-:|:-:|:-:|:-:|---|
| `trained_yet + recency` | ✓ | ✓ | — | — | benchmark 는 학습 대상이 아님 |
| `direction * time_c` | ✓ | ✓ | ✓ | ✓ | 공통 |
| `depth_num + is_proj` | — | ✓ | — | ✓ | probing 만 층 축 있음 (연속, 아래 참조) |
| `(1\|cell)` | — | ✓ | — | ✓ | probing 만 층 반복 |

커리큘럼에서 `time_c` 단독 기여는 0 이다 — `time` 이 1..5 정수라 `trained_yet`/`recency` 와
중복되기 때문. 그래도 `direction*time_c` 형태로 두어 네 분석의 「방향」·「학습량」 줄이 정확히
같은 것을 재게 맞춘다.

## depth 를 연속으로 넣는 이유 (범주형 아님)

모델마다 총 층수가 달라(대부분 32, openflamingo 24) 절대 층 번호로는 비교 불가. 모델별로
`(층번호 / 마지막 층번호)` 로 정규화하면 다섯 모델이 0/.25/.5/.75/1 격자에 겹친다(`depth_num`).
`proj`(비전→언어 프로젝터)는 LLM 층과 종류가 달라 같은 축에 놓지 않고 별도 지시변수(`is_proj`)로 둔다.

처음엔 depth 를 6수준 **범주형**으로 넣었으나, 프로파일이 사실상 **직선**이라 연속 1차로 바꿨다:

| | 범주형 | 직선(depth_num) | 2차(poly 2) |
|---|---|---|---|
| AIC | −5621 | **−5637** | −5638 |
| 2차항 검정 | — | — | χ²(1)=1.9, p=0.17 |

직선이 범주형보다 AIC 가 낮고, 2차항을 더해도 개선이 없다(p=0.17). 앞서 "0.75 에서 포화"처럼 보였던
꺾임은 추정 잡음이었다. 그래서 계수 5개 대신 **`depth_num` 기울기 하나**로: 한 층 깊어질 때 delta
증가량(≈ +0.05). 해석이 깨끗해지고 검정력도 오른다. `direction × depth_num` 도 계수 하나로,
"방향에 따라 깊이 기울기가 다른가"를 직접 검정한다(탐색적, exploratory_direction.md).

**`layer_0`(깊이 0)은 프로브 바닥값이다.** 트랜스포머 블록을 하나도 통과하지 않은 입력 임베딩이라
프로브가 학습할 신호가 없어 다수클래스만 찍는다 — 아키텍처가 다른 5개 모델이 소수점 4자리까지
같은 값을 내고(0.0667=1/15 등) 학습 내내 미동도 없다. 연속 기울기(`depth_num`)에서는 이 바닥점이
직선의 한쪽 끝을 잡아줄 뿐 왜곡하지 않는다. 깊을수록 성장이 커지는 것 자체가 결과다: 정보는
후반부 층에서 자란다.

## 방향 기준 (forward / reverse)

`direction` 은 2수준이라 **기준을 바꿔도 모형·적합·p값·결론은 불변**이다(AIC 동일). 바뀌는 것은
(1) `direction` 계수의 부호, (2) `direction` 과 상호작용하는 항의 조건부 의미뿐이다. 기본 기준은
**forward** 로 두어 `directionreverse` = "커리큘럼을 뒤집으면"으로 읽는다. 노트북은 각 분석에
reverse 기준 방향 계수도 함께 출력한다(부호 반전 확인용). 그림도 forward 기준(`reverse−forward`,
`curriculum_*.pdf`)과 reverse 기준(`forward−reverse`, `*_fwdref.pdf`) 두 세트로 제공한다.

## 결측

- probing 은 결측 없음.
- inference benchmark 는 67건, **openflamingo·vila_8b 에 몰려** 있다. 지금은 그 행을 버리는
  완전사례 분석이라 두 모델의 기여가 과소추정될 수 있다.
- 실패(NaN) 자체를 결과로 보는 모형(사양 MF)은 하지 않았다: (1) 사건이 2개 모델에 몰려 준완전
  분리, (2) 시간에 따른 증가 없음, (3) 실패한 21개 계열 중 19개가 회복 — "출력 붕괴"가 아니라
  간헐적 파싱 실패로 보여 사양의 전제("모델 유발 붕괴")에 맞지 않는다.

## 결과 읽을 때 주의

- `base_wi` 음수는 자동이다(응답이 delta 라 수준 모형 대비 −1). 평균회귀 성분 포함.
- `task` 분산성분이 probing·benchmark 에서 0(singular)이다. 모델 공통의 태스크 효과가 없다는
  뜻(모델마다 다름)이고 계수에는 영향 없다. 그대로 둔다.
- probing benchmark 의 유의한 소수 계수(`direction` 등)는 효과 크기가 0.001~0.004 로, 수천 행의
  힘으로 잡힌 것이지 실질적 의미는 없다.
- 모든 결론은 모델 5개·커리큘럼 태스크 5개·benchmark 10개 위의 것. 모델 수준 효과는 df 3~4.
- llava 의 `base` 가 forward/reverse 파일에서 2개 셀만 미세하게 다르다(재측정 노이즈). 무시.
